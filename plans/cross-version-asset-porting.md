# Cross-version asset porting: Unity 2022.3 → Alterum 6000.3.16f1

## Decision and hard boundary
- Reconstruct cosmetics from engine-neutral data. Reconstruct emote **poses**, not Mecanim clips, unless an external matching-Editor conversion step becomes available.
- **There is no supported runtime API to compile new Generic/Humanoid AnimationClips for Animancer.** Runtime `SetCurve` creates usable Legacy animation; Animancer uses Playables and rejects Legacy clips. These are different pipelines, not interchangeable flags. Unity explicitly says Animator needs an optimized representation whose compilation is unavailable at runtime. [1][2]
- Therefore “new imported emotes must be actual AnimationClips played by Animancer” is not reliably achievable under the stated constraints. Agree to a CPU pose-player bridge alongside Animancer, or obtain bundles compiled by a Unity 6000.3.16f1 Editor elsewhere. Do not promise a drop-in `AnimationClip` replacement.
- This is a design only: no original-bundle loading experiments, runtime inspection, builds, or game changes are required to produce it.

## 1. Ranked animation techniques
1. **CPU pose playback: supported primitives; recommended.** For Generic/transform sources, extract full local position/quaternion/scale tracks plus reference skeleton. For verified Humanoid sources, extract semantic muscle/body tracks instead. Ship sampled tracks in `emotes/*.bin` plus manifest metadata. Runtime brackets samples by playback time, interpolates translations/scales with `Vector3.Lerp` and rotations with `Quaternion.Slerp`, then uses `Transform.SetLocalPositionAndRotation`, `localScale`, or `HumanPoseHandler.SetHumanPose(ref pose)` respectively (scalar interpolation for muscles). This is an emote player, **not an AnimationClip**; arbitration with Animancer is mandatory (§3).
2. **Legacy clip on an isolated helper skeleton: supported; useful evaluator.** Extract transform curves with relative paths, key times/values/tangents/wrap settings; ship curve records in the same pack. Runtime constructs `new AnimationClip { legacy = true }`, calls `SetCurve`, then `clip.SampleAnimation(helperRoot, time)` and copies/retargets resulting transforms to the visible rig. Alternatively `helperRoot.AddComponent<Animation>()`, `AddClip(clip, id)`, `Play(id)`. Keep the Legacy evaluator off the live Animator hierarchy. This preserves Unity curve evaluation, but still does not produce an Animancer-compatible clip. [1]
3. **Externally compiled target-version clip: only dependable literal Animancer route; unavailable locally.** Export transform tracks as a documented interchange payload, then have a matching Editor import/bake them into Generic clips, or import/retarget Humanoid clips using a valid source Avatar. Ship the resulting target-platform bundle. Runtime: `AssetBundle.LoadFromFile`, `bundle.LoadAsset<AnimationClip>(name)`, `animancer.Play(clip, 0.2f)`. Preserve assets if unloading the bundle container. This is a future escape hatch, not a required step in the no-Editor pipeline.
4. **Native-format transcoding / flag hacks: research only.** Building a valid Unity-6 serialized clip, bindings, compressed curves and bundle from target-schema templates might avoid an Editor, but is a bespoke native serializer/compiler project. Do not put it on the delivery path. Setting `legacy=false` after `SetCurve` does not supply the missing Mecanim compilation. [1][2]

### What SetCurve actually supports
- Paths are slash-delimited names **relative to the GameObject being sampled/animated**: e.g. `Armature/Hips/Spine`; `""` addresses that root. Supply the component type and animatable property, not a humanoid semantic bone name.
- Transform examples: `localPosition.x/y/z`, `localRotation.x/y/z/w`, `localScale.x/y/z`; author all quaternion components, normalize samples, then call `clip.EnsureQuaternionContinuity()`. Prefer quaternion tracks over discontinuous Euler tracks.
- Example runtime calls: `var c = new AnimationClip { legacy = true }; c.SetCurve(path, transformType, "localRotation.w", curve); c.EnsureQuaternionContinuity(); c.SampleAnimation(helperRoot, t);` Build `curve` with `new AnimationCurve(keys)` or `AddKey(new Keyframe(t,v,inTan,outTan))`.
- In IL2CPP interop, `transformType` is `Il2CppInterop.Runtime.Il2CppType.Of<Transform>()`, not necessarily CLR `typeof(Transform)`; use generated wrapper signatures and IL2CPP arrays. Preserve weighted-tangent metadata where supported, or bake offline to samples.
- Legacy curves animate exposed component properties; writing names like `"Left Arm Down-Up"` on `Animator` does **not** construct Humanoid muscle bindings or invoke retargeting. Generic clips are non-Legacy transform clips and have the same runtime-compilation barrier as Humanoid clips.
- `UnityEditor.AnimationUtility.SetEditorCurve(s)` is Editor-only. Neither copying UnityEditor.dll into BepInEx nor calling `AnimatorOverrideController`/`AnimationClipPlayable.Create` compiles curves in a Player. `AnimationClip.legacy` changes classification, not conversion. [1][3]

### Decode first; do not confuse parsing with Humanoid baking
- Inventory each clip's legacy/humanoid metadata, binding types, duration, frame rate, root-motion settings and referenced Avatar/skeleton. The presence of `m_MuscleClip` alone does **not** prove Humanoid: Generic runtime tracks can also live there.
- Extract ordinary rotation/position/scale curves **and** packed `m_MuscleClip.m_Clip` streamed/dense/constant sections; decode compression and resolve `m_ClipBindingConstant` using the exact source version. Resolve hashed paths from the source prefab/Transform hierarchy and Avatar metadata; do not pretend hashes are reversible names. [4]
- Streamed, dense and constant scalar indices share one binding space; respect vector/quaternion widths, source start time, interpolation and constant/default channels. Export unresolved bindings as errors, never silently discard them. An FBX/OBJ exporter that ignores Animator bindings can produce an apparently successful but motionless export. [4]
- For verified Humanoid Animator bindings, map muscle channels to the **documented semantic order** exposed by `HumanTrait.MuscleName`/`HumanTrait.MuscleCount`; retain source binding IDs for audit. Do not equate packed scalar indices or attribute IDs directly with muscle-array indices. Body, root, IK goals and translational degrees of freedom are distinct channels, not extra muscles.
- **UnityPy is a decoder, not Unity's Humanoid solver.** It cannot turn arbitrary muscle curves into correct bone transforms merely by exporting curves. Without a validated semantic decoder, source rig/Avatar information, or an external Unity evaluator, exact Humanoid baking is blocked; ship a clearly marked approximation or stop that clip.

### Runtime Humanoid retargeting without an Editor
- If muscle/body semantics have been decoded, construct `new HumanPoseHandler(targetAnimator.avatar, targetAnimator.transform)` after checking `avatar != null && avatar.isValid && avatar.isHuman`. Allocate `HumanPose.muscles` once to `HumanTrait.MuscleCount`; fill normalized muscle values per frame and call `handler.SetHumanPose(ref pose)`. Dispose the handler on model destruction. **A source clip need not be loaded.** [5]
- Supply a valid `bodyRotation` and normalized, root-relative center-of-mass `bodyPosition`; it is not hip localPosition or controller root-motion delta. Preserve a known neutral/reference pose for absent channels. Begin with in-place emotes and separately retain root trajectory metadata; do not move the physics/network player root from animation data. [5]
- RootT/RootQ, motion extraction, source import options, foot IK and extra translation channels require explicit conversion/validation; muscle playback alone is not guaranteed to reproduce source root motion or foot locking. Accept that approximation before porting the full emote set.
- If only source bone tracks exist, reconstruct the source reference skeleton, evaluate it, then use a source `HumanPoseHandler.GetHumanPose(ref pose)` and the target `SetHumanPose` to retarget. Obtain/build the source Avatar with `AvatarBuilder.BuildHumanAvatar(sourceRoot, HumanDescription)` and check validity; this needs correct `HumanBone[]`, `SkeletonBone[]`, T-pose and limits, not just names. [5][6]
- Get/Set body-coordinate conventions are not identical: Get reports normalized world COM, Set expects normalized root-relative COM. Convert deliberately; use identity-position/rotation, unit-scale helper roots to simplify initial validation. Never blindly copy a world-space body pose onto a moved player. [5]
- This can also bake target bone samples **inside a future runtime loader on a hidden clone**, then CPU-play them. It is runtime baking, not offline UnityPy-only baking, and still cannot compile a Generic AnimationClip.

## 2. Rig compatibility rules
- Generic/Legacy path binding requires matching relative names **and hierarchy**, including added wrapper nodes and hierarchy depth. A matching leaf name is insufficient. Rebind paths explicitly or resolve a semantic source→target bone map once; fail on ambiguous duplicates.
- For CPU transforms, account for different rest rotations, bone axes, lengths, root scale and intermediary/twist bones. Transfer rotations through calibrated reference-pose frames; preserve target limb translations/lengths by default. Naively copying source local rotations or positions causes twisted limbs or distorted proportions.
- Humanoid retargeting does not require equal names/depth across source and target; each Avatar must correctly map its own hierarchy to human semantics and be built from an appropriate T-pose, with valid limits and scale. Missing fingers/twist/extra bones lose motion; nonhuman bones require additional transform tracks.
- If Alterum's actual model has no valid Humanoid Avatar, the direct HumanPose route is unavailable. Prefer CPU transform mapping; building a temporary valid Avatar is an optional explicit rig-authoring task, not automatic recovery. Do not overwrite the game's Avatar as a casual fix.

## 3. Animancer and IL2CPP integration contract
- Keep the game's existing third-person Animator/Animancer pair; do not attach a competing Animator or Legacy Animation to its hierarchy. Resolve the third-person model and its controller per spawn; do not assume the first-person arms rig is equivalent.
- **Actual compiled clip only:** `var state = animancer.Play(clip, 0.2f); state.Time = 0; state.Speed = 1;` or `animancer.Layers[layerIndex].Play(clip, 0.2f)` if that overload exists in the shipped Animancer version. Layer masks must also already be valid; locomotion/state logic must yield to the emote.
- **Pose payload:** expose `EmotePlayer.Start(id, startTime)`, `Tick(dt)`, `Stop()` in a mod-owned controller. Acquire exclusive ownership of selected bones or pause the game's animation through its existing ownership/disable mechanism. Apply poses on the Unity main thread after Animator evaluation **and after competing rig/IK writers**; blend out and return ownership on cancel, death, movement, despawn or model swap. A bare LateUpdate is not proof of correct ordering.
- If keeping locomotion underneath, capture its evaluated pose and blend selected transforms/muscles before applying the override; preserve unmasked bones. Root motion, event timing and cancellation must be implemented explicitly. Synchronize emote ID/start time, not per-frame transforms, when multiplayer support is added.
- A custom Animancer state/job is not a magic clip converter. New managed `IAnimationJob` structs require native/AOT support; a CoreCLR plugin cannot assume Unity IL2CPP has generated their job glue. Prefer a registered IL2CPP MonoBehaviour/main-thread callback; defer graph-native jobs unless an existing compatible native job is proven usable. [7]
- Use `ClassInjector.RegisterTypeInIl2Cpp<T>()` plus the generated `IntPtr` constructor for injected components; use `Il2CppStructArray<T>`/`Il2CppReferenceArray<T>` or available array overloads. Cache all native references/bone maps; never allocate textures, meshes, pose arrays or handlers each frame.

## 4. Ranked cosmetic techniques and exact reconstruction
1. **Rigid MeshFilter + MeshRenderer under Head: recommended for hats/accessories.** Extract mesh attributes/submeshes, material slots, textures and prefab-local transforms. Ship numeric mesh buffers + manifest + RGBA8 texture buffers. Runtime reconstructs a mesh/material, finds `animator.GetBoneTransform(HumanBodyBones.Head)` (or a validated explicit path), then `cosmetic.transform.SetParent(head, false)` and applies a target-specific fit offset/rotation/scale.
2. **Preserve an accessory's own internal skeleton under Head.** Extract its complete Transform hierarchy/rest TRS, weights and bindposes; rebuild with `new GameObject`, `SetParent`, then `AddComponent<SkinnedMeshRenderer>()`, assigning `sharedMesh`, `bones`, `rootBone`, `sharedMaterials`, `localBounds`. Keep source mesh-space/bone transforms consistent; add CPU tracks if it has accessory animation. This avoids mapping accessory bones into the player's entire rig.
3. **Retarget multi-bone skinning onto target player bones: last resort.** Extract source skeleton/reference pose and renderer transforms alongside mesh data. Map each weight's bone index to target semantic bones, align mesh/rest frames, then compute target bindposes at the intended reference pose: `bindposes[i] = targetBone[i].worldToLocalMatrix * cosmetic.transform.localToWorldMatrix`. Weights, bindpose order and `renderer.bones` order must agree. Do not reuse unrelated source bindposes or compute bindings while the target is mid-animation. [8]

### Mesh calls and the one-bone escape hatch
- Construct `var mesh = new Mesh(); mesh.indexFormat = UnityEngine.Rendering.IndexFormat.UInt32;` before assigning large index buffers; call `SetVertices(vertices)`, `SetNormals(normals)`, `SetTangents(tangents)`, `SetUVs(0, uv0)` (and other channels if needed), optionally `SetColors(colors)`; set `subMeshCount`, then `SetTriangles(indices, submesh)` for every material slot, preserving/resolving source baseVertex.
- Set `mesh.bindposes = matrices` (or `SetBindposes(NativeArray<Matrix4x4>)`); set `mesh.boneWeights = fourWeightArray` for ≤4 influences. For full influence counts use `mesh.SetBoneWeights(NativeArray<byte> bonesPerVertex, NativeArray<BoneWeight1> weights)`, descending weights per vertex and normalized sums; dispose temporary NativeArrays afterward. Prefer array/property overloads when CoreCLR→IL2CPP NativeArray marshaling is unavailable. If reducing to four influences, record and validate the lost weight. [8]
- Finish with `RecalculateBounds()`; preserve exported normals/tangents where possible, otherwise `RecalculateNormals()` and `RecalculateTangents()` after valid UVs. Create `MeshFilter.sharedMesh = mesh` and `MeshRenderer.sharedMaterials = materials`, or the skinned equivalents. Keep meshes readable until validation; use `UploadMeshData(true)` only when no CPU access is needed.
- To rigidify a skinned hat, offline evaluate its **reference pose**: `pMesh = rendererWorldInverse * Σ(weight * boneWorld * bindpose * pSource)`, then transform `pMesh` into source-head local coordinates. Transform normals/tangents correctly too. Ship the resulting static mesh and rigid-parent it; deleting weights without this coordinate conversion can offset or deform the accessory.
- If a SkinnedMeshRenderer is required for a rigid object, use one head bone with weight 1 for every vertex, renderer parented at identity to Head, and identity bindpose for head-local vertices. Otherwise a MeshRenderer is cheaper. Set a conservative `localBounds` on skinned renderers; diagnose culling before enabling costly `updateWhenOffscreen` globally.

### Textures/materials: replace the shader, translate selected meaning
- Decode Texture2D with UnityPy to **uncompressed RGBA8**, mip 0; record width/height, color-space intent, wrap/filter settings and pixel-row convention. Do not pass compressed source GPU blocks to an RGBA32 texture. Preserve vertex/UV conventions; validate a numbered/checker texture before compensating with arbitrary flips.
- Runtime: `new Texture2D(w, h, TextureFormat.RGBA32, true, linear)` → `LoadRawTextureData(bytes)` → `Apply(true, false)`; use `linear=false` for albedo, `true` for masks/normal data. An optional PNG route is `new Texture2D(2,2,TextureFormat.RGBA32,false,linear)` + `ImageConversion.LoadImage(texture, pngBytes, false)`; LoadImage uploads automatically. There is no general Unity `LoadRawImage` API. [9]
- Prefer `new Material(existingTargetUrpMaterial)` from a known opaque/unlit or lit template already shipped with the game. Fallback: `Shader.Find("Universal Render Pipeline/Unlit")` or `Shader.Find("Universal Render Pipeline/Lit")`, check null and support, then `new Material(shader)`. Finding a shader name does not ensure required variants survived stripping. [10]
- Translate `_MainTex`→`_BaseMap`, `_Color`→`_BaseColor`; use `SetTexture`, `SetColor`, `SetTextureScale`, `SetTextureOffset`, `SetFloat` only after `HasProperty`. Preserve UV tiling/offset, base color/alpha and simple emissive meaning. Start opaque URP/Unlit; adopt a matching existing cutout/transparent template for those modes rather than setting `_Surface` alone.
- For URP/Lit, reconstruct `_MetallicGlossMap` (metal R, smoothness A), `_Metallic`, `_Smoothness`, `_BumpMap`/`_BumpScale`, `_EmissionMap`/`_EmissionColor`, and needed keywords only when supported by the chosen shader variant. Built-in specular workflows need conversion or a specular template. Repack HDRP masks (metal R, AO G, detail B, smoothness A) into URP's separate maps; decode source normal encodings/swizzles before repacking for the target shader. Otherwise omit normals/masks initially.
- Shader bytecode, HDRP/built-in passes, custom lighting, subsurface/detail effects and arbitrary keywords do not transfer. Material property blocks are input metadata, not portable shaders. Transparent blend/ZWrite/renderQueue/cull settings must come from a coherent target template; no Editor means no ordinary compilation of missing shader variants.

## 5. Concrete deliverable pipeline
1. Implement a future `extract_assets.py` using pinned UnityPy + image decoder, outside the runtime mod. Enumerate requested prefabs/clips and follow PPtrs into bundled/external resources. Extract dependency-complete geometry, reference rigs, packed curves and material metadata; never copy MonoBehaviour logic, source shaders or executable AnimationEvents.
2. Recommend one container: **`assets.apack` = ordinary ZIP**, versioned `manifest.json` + little-endian float32/uint32 binary buffers + raw RGBA8 textures. ZIP compresses raw pixels well and avoids adding a glTF/FBX importer. Manifest records byte offsets/counts, stride, endianness, hashes, units, coordinate convention, source object IDs, bounds, submeshes/materials, reference TRS, bone maps, texture semantics, and per-emote duration/loop/root policy.
3. Bake decoded transform tracks at 60 Hz initially; store float32 local position/quaternion/scale with quaternion sign continuity. Store verified Humanoid samples as semantic muscles + normalized body pose, separately from root/IK tracks; retain original decoded bindings/curve metadata for diagnostics. Increase sample rate only when fast motion visibly needs it. Do not label muscle samples as baked bone transforms.
4. Ship `BepInEx/plugins/AlterumPorts/AlterumPorts.dll` beside `assets.apack`; sidecar data is easier to replace/debug than embedded resources. Resolve relative to the plugin assembly, not process CWD. Embed only tiny defaults; enforce asset redistribution permissions.
5. Future `PortAssetLoader` reads/validates ZIP+JSON off-thread, checks sizes/indices/bone counts, caches decoded managed buffers; schedules **all UnityEngine object construction on the Unity main thread**. Build mesh/texture/material caches once, instantiate cosmetic hierarchies per player, and create `EmotePlayer` per model. Lazy-load selected assets, not every emote at startup.
6. Keep a source asset ID→reconstructed object/prefab registry; replace the mod's original `LoadAsset` call sites with this registry. Recreate prefab hierarchy/components explicitly; asset reconstruction is not a binary-compatible bundle or behaviour replacement. Use known source attachment metadata as defaults, then target-specific fitting.
7. Proposed acceptance order: one static hat/checker texture → one rigidified skinned hat → one Generic pose track → one decoded Humanoid emote. Check first/middle/last/loop-seam poses and cancellation. Gate expansion on correct rig mapping and ownership; no full-pack work before those pass.

## 6. Failure modes / stop conditions
| Symptom | Likely cause / action |
|---|---|
| Emote clip exists but Animator/Animancer is motionless or rejects it | Legacy/non-Legacy compilation barrier; switch to pose bridge, not another Play call. |
| Pose is static despite successful extraction | Missing streamed/dense/constants, unresolved Animator bindings or silently dropped muscles; fail extraction. |
| Some bones never animate | Wrong root-relative path, missing hierarchy nodes, duplicate names, optimized/unexposed bones or incomplete map; resolve explicitly. |
| Twisted limbs, exploding scale, sliding feet | Wrong rest frames, quaternion order/sign, source→target lengths, body/root conversion or missing IK; validate one joint/pose first. |
| Hat explodes or floats away | Bone-index/order mismatch, wrong mesh space/bindposes/reference pose; rigidify first. |
| Pink/black/flat/inside-out hat | Missing shader/variant, wrong color space/normal packing, absent light, flipped winding or normals; use known target Unlit template/checker. |
| Hat vanishes at angles or only in some views | Skinned bounds, camera layer masks, LOD or first/third-person visibility policy; inherit target conventions, never LC layer numbers. |
| Pose flickers or immediately resets | Animancer, locomotion, IK or another writer owns the bones later; solve scheduling/ownership before changing data. |
| Runtime API/type missing or interop errors | Stripped native API/AOT generic specialization or CLR-vs-IL2CPP arrays/types; use available wrapper overloads and CPU callbacks. |
- Exact source humanoid retarget/root-motion/IK parity from opaque packed curves is not a free UnityPy feature; stop unsupported clips rather than guessing. Native Animancer clips, shader compilation, arbitrary bundle recompilation and new native animation-job glue remain outside the supported no-Editor path.

## 7. Cheap alternatives: assess, then time-box
- Reuse existing Alterum compiled clips via Animancer for functional emote UI/network scaffolding; this is **not** a port of BetterEmotes motion. Obtain neutral source meshes/PNGs/rig tracks from authors where possible; they may remove substantial extraction work.
- Unity bundles are **not universally locked to one exact Editor version**: newer Players can sometimes read older type-tree-backed assets. That does not override the task's observed/assumed failure of these original bundles. Do not retry original LoadFromFile as the plan. [11]
- Disabling type trees makes version/schema adaptation worse, not better; it cannot retrofit an already-built bundle into Unity 6. A serialized-file format version is a structural contract, not a compatibility knob. [11]
- UnityFS wrapper version, producer version string, SerializedFile format version, type trees and object payload layouts are different layers. UnityPy can rewrite/save containers and version metadata, but changing headers does not convert meshes, compressed animation bindings, shaders or native schemas. A metadata-only rejection is the narrow case where spoofing might pass; it is not evidence of valid assets. [12]
- A genuinely rewritten bundle would require target type layouts, references, sizes/alignment and per-class migrations; Animancer clips still need valid compiled native animation data. If the hard clip requirement persists, seek an external matching-Editor batch conversion rather than invest in header spoofing or a serializer compiler.
